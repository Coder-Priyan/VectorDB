# VectorDB Benchmark Results Schema

This directory contains CSV benchmark exports generated by `vectordb_demo`.

All benchmarks adhere to rigorous scientific methodology:
- Single-threaded query execution.
- 1 warm-up pass, followed by 5 timed repetitions (3 repetitions in `--quick` mode).
- Timings report the **median** of the per-repetition average query latency, along with **min** and **max**.
- Ground-truth nearest neighbors and baseline query latency are computed using `BruteForceIndex` measured **once** per $(n, \text{dim}, \text{metric})$ and reused across comparisons.
- Identical random seeds (`seed=42` for datasets, `seed=1337` for query sets).

---

## CSV Schemas

### 1. `build.csv`
Structural layer distribution and build performance for HNSW:
- `n`: Total number of indexed vectors.
- `dim`: Dimensionality of vectors.
- `metric`: Distance metric (`euclidean`, `cosine`, `manhattan`).
- `M`: Maximum outgoing edges per node for layers $\ge 1$.
- `efConstruction`: Size of dynamic candidate list during graph construction.
- `seed`: Random seed for graph level generation.
- `build_time_ms`: Total wall-clock indexing time in milliseconds.
- `max_level`: Highest graph layer present in the index.
- `entry_point_id`: VectorId of the root node located at `max_level`.
- `layer`: Graph layer index ($0 \dots \text{max\_level}$).
- `nodes`: Number of vectors present on this layer.
- `pct_of_total`: Percentage of total vectors present on this layer ($(\text{nodes} / n) \times 100$).
- `avg_degree`: Average outgoing degree of nodes on this layer.

### 2. `ef_sweep.csv`
Trade-off analysis between search accuracy (Recall@10) and query latency across different beam search widths:
- `n`, `dim`, `metric`, `M`, `efConstruction`, `seed`: Dataset and graph parameters.
- `efSearch`: Size of the dynamic candidate list during search traversal on layer 0.
- `recall_at_10`: Mean Recall@10 evaluated against exact Brute Force ground truth.
- `median_query_ms`: Median per-query latency in milliseconds across timed repetitions.
- `min_query_ms`: Minimum per-query latency observed across timed repetitions.
- `max_query_ms`: Maximum per-query latency observed across timed repetitions.
- `qps_median`: Queries per second based on median query time ($1000.0 / \text{median\_query\_ms}$).
- `speedup_vs_bf`: Speedup factor relative to Brute Force median query time ($\text{bf\_median} / \text{hnsw\_median}$).
- `dist_comps_pct`: Average distance computations per query expressed as a percentage of $n$.
- `avg_dist_comps`: Average absolute number of distance computations per query.
- `bf_median_query_ms`: Baseline Brute Force median query latency (ms).

### 3. `m_sweep.csv`
Impact of graph connectivity parameter $M$ on construction latency, query speed, accuracy, and graph memory footprint:
- `n`, `dim`, `metric`, `M`, `efConstruction`, `efSearch`, `seed`: Benchmark configuration.
- `build_time_ms`: Wall-clock index construction time in milliseconds.
- `recall_at_10`: Mean Recall@10 against Brute Force ground truth.
- `median_query_ms`, `min_query_ms`, `max_query_ms`: Query latency statistics.
- `qps_median`: Queries per second based on median query time.
- `graph_memory_kb`: Estimated memory footprint for graph neighbor lists ($\sum \text{degree} \times 4\text{ bytes} / 1024$).
- `bf_median_query_ms`: Baseline Brute Force median query latency (ms).

### 4. `dim_compare.csv`
Three-way index comparison (Brute Force vs KD-Tree vs HNSW) across dimensions $d \in \{8, 16, 32, 64, 128\}$:
- `n`, `dim`, `metric`, `k`, `seed`: Problem configuration.
- `bf_median_ms`, `bf_min_ms`, `bf_max_ms`: Brute Force baseline latency statistics (ms).
- `kd_median_ms`, `kd_min_ms`, `kd_max_ms`: KD-Tree latency statistics (ms).
- `kd_speedup`: KD-Tree speedup factor ($\text{bf\_median} / \text{kd\_median}$).
- `kd_recall`: KD-Tree Recall@10 (always 1.000 for exact search).
- `hnsw_median_ms`, `hnsw_min_ms`, `hnsw_max_ms`: HNSW latency statistics (ms).
- `hnsw_speedup`: HNSW speedup factor ($\text{bf\_median} / \text{hnsw\_median}$).
- `hnsw_recall`: HNSW Recall@10.

### 5. `metrics.csv`
Non-Euclidean metric comparison for Cosine and Manhattan similarity at $d = 128$:
- `n`, `dim`, `metric`, `M`, `efConstruction`, `efSearch`, `seed`: Configuration parameters.
- `bf_median_ms`: Brute Force median query latency (ms).
- `hnsw_median_ms`, `hnsw_min_ms`, `hnsw_max_ms`: HNSW query latency statistics (ms).
- `speedup_vs_bf`: HNSW speedup factor relative to Brute Force.
- `recall_at_10`: HNSW Mean Recall@10.
