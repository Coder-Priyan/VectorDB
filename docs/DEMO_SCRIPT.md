# VectorDB Viva Demonstration Script (6 to 8 Minutes)

This script is structured as chronological numbered steps for an interactive academic viva or project demonstration.
Each step indicates the target tab and URL hash, the user action, what the audience sees, a one-sentence architectural explanation, and specific viva talking points regarding capabilities and limitations.

---

### Step 1: System Boot & Health Verification
- **Tab & URL**: Settings (`http://127.0.0.1:8080/#settings`)
- **Action**: Open the browser to `#settings` and observe the server status panel and the Ollama status badge in the header.
- **Audience Sees**: Server version (`0.4.0`), active index configuration (dimensions, distance metric, HNSW hyperparameters $M=16, \text{efConstruction}=200$), and a green `Ollama Online` status badge showing local model readiness (`nomic-embed-text` and `llama3.2`).
- **Explanation**: The web UI communicates with a high-performance C++17 HTTP server via non-blocking REST endpoints, verifying local LLM daemon availability prior to query execution.
- **Viva Defense Point**: The entire system operates 100% offline with zero external network calls, ensuring total data privacy.

---

### Step 2: Document Ingestion & Transparent Chunking
- **Tab & URL**: Ask (`http://127.0.0.1:8080/#ask`)
- **Action**: Select the sample text document `samples/vectordb_intro.txt` (or paste plain text) and click **Ingest Document**.
- **Audience Sees**: An ingestion progress spinner, followed by the document card appearing in the ingested documents list displaying chunk count, file size, timestamp, and a collapsible chunk inspector showing exact sentence boundary splits with character offsets.
- **Explanation**: The C++ ingestion pipeline segments documents into deterministic chunks using sliding windows with configurable overlap, and embeds them into 768-dimensional vectors via Ollama's local embedding API.
- **Viva Defense Point**: Chunk boundaries preserve complete sentences to maintain semantic coherence, and all ingested documents are indexed across all three algorithms simultaneously.

---

### Step 3: Grounded Q&A with Live SSE Streaming
- **Tab & URL**: Ask (`http://127.0.0.1:8080/#ask`)
- **Action**: Enter the question `"How does HNSW achieve logarithmic search time?"` and click **Ask Question**.
- **Audience Sees**: A *Thinking...* status notification while top chunks are retrieved, immediately followed by the LLM response streaming in real-time token-by-token via Server-Sent Events (SSE), rendered safely as pure text nodes with inline citation pills like `[1]` and `[2]`.
- **Explanation**: The C++ server embeds the prompt query, retrieves top-$k$ relevant chunks using cosine similarity, constructs a grounded system prompt enforcing strict attribution, and streams the Ollama LLM completion over HTTP chunked transfer encoding.
- **Viva Defense Point**: Responses are strictly grounded in retrieved document context; if the knowledge base lacks information, the prompt explicitly forces the model to refuse rather than hallucinate.

---

### Step 4: Interactive Citation Drill-down & Source Verification
- **Tab & URL**: Ask (`http://127.0.0.1:8080/#ask`)
- **Action**: Click on an inline citation pill (e.g. `[1]`) within the generated answer.
- **Audience Sees**: The interface scrolls down and highlights the corresponding source card, displaying the chunk's source document title, chunk index, cosine similarity score bar, and the exact chunk text.
- **Explanation**: The frontend splits streaming text into plain text spans and citation tokens, establishing DOM element references between citations and source chunk cards without using `innerHTML`.
- **Viva Defense Point**: Every fact generated by the LLM can be audited against the primary text chunks retrieved by the vector index.

---

### Step 5: 2D PCA Vector Space Exploration
- **Tab & URL**: Explore (`http://127.0.0.1:8080/#explore`)
- **Action**: Click the **Explore (PCA)** tab; select the Demo collection (2,000 vectors) or Documents collection; use the mouse wheel to zoom into a cluster, drag to pan, and hover over individual points.
- **Audience Sees**: A responsive HTML5 2D scatter plot showing projected vectors with explained variance ratios on both axes ($PC_1$ and $PC_2$), an interactive document color legend, and an 8-pixel hover tooltip displaying vector ID, coordinates, and document chunk titles.
- **Explanation**: A zero-dependency C++ Principal Component Analysis (PCA) engine reduces high-dimensional vector spaces down to two principal variance axes using power iteration and Rayleigh quotient deflation.
- **Viva Defense Point**: The 2D projection is an exploratory approximation; while relative cluster proximity is preserved, higher-dimensional nuances are compressed onto the top two eigenvectors.

---

### Step 6: Semantic Nearest-Neighbor Projection Query
- **Tab & URL**: Explore (`http://127.0.0.1:8080/#explore`)
- **Action**: Enter a query or click **Query Random**, and click **Search**.
- **Audience Sees**: A gold star plotted at the query vector's projected coordinates, connecting line segments drawn to the top-$k$ nearest neighbors on the map, and a synchronized side table listing neighboring IDs, distances, and similarity percentages.
- **Explanation**: The query vector is projected onto the pre-computed principal component eigenvectors in $O(d)$ time and visualized alongside index vectors in data-space coordinates.
- **Viva Defense Point**: Nearest neighbors in 768-dimensional space are geometrically faithful in full precision, even when 2D projections show slight visual overlap due to dimensionality reduction.

---

### Step 7: HNSW Proximity Graph Hierarchy Navigation
- **Tab & URL**: HNSW Graph (`http://127.0.0.1:8080/#hnsw`)
- **Action**: Switch to the **HNSW Graph** tab; slide the **Layer** control from layer 0 up to the maximum layer (e.g. layer 3 or 4).
- **Audience Sees**: The graph topology dynamically redraws on canvas: layer 0 displays the dense multi-edge base graph; higher layers progressively thin out showing sparse skip-list highway connections, with the global entry point highlighted by a glowing amber ring.
- **Explanation**: Malkov's Hierarchical Navigable Small World (HNSW) structure organizes nodes into geometric layers where node presence decays exponentially by layer, achieving $O(\log N)$ search complexity.
- **Viva Defense Point**: Dense lower layers are buffered via an offscreen canvas to maintain 60 FPS viewport rendering even when displaying tens of thousands of edges.

---

### Step 8: Step-by-Step Search-Path Traversal Animation
- **Tab & URL**: HNSW Graph (`http://127.0.0.1:8080/#hnsw`)
- **Action**: Click **Random** under Search Path Step Trace, then press **Play** (or use the step forward `▶` button).
- **Audience Sees**: The animation traces the search traversal from the top layer down to layer 0: hops illuminate chronologically, visited nodes change color per layer, connecting traversal lines follow greedy routing, and traversal diagnostics (distance computations, visited counts per layer) update in real-time.
- **Explanation**: The C++ server records the exact greedy search path across layers using an observability trace hook and exports the sequential hops over the REST API.
- **Viva Defense Point**: Visualizing the search path proves that HNSW navigates coarse clusters at high layers before zooming into fine-grained local neighborhoods at layer 0.

---

### Step 9: Multi-Algorithm Benchmark Comparison
- **Tab & URL**: Compare (`http://127.0.0.1:8080/#compare`)
- **Action**: Switch to the **Compare** tab; select **5 Repetitions**; click **Benchmark Random Query**.
- **Audience Sees**: A status message indicating the warm-up pass followed by sequential iterations; once complete, a metrics table and comparative horizontal canvas bars appear comparing Brute Force, KD-Tree, and HNSW across Latency ($\mu s$), Distance Computations, and Recall@k.
- **Explanation**: The collection executes the query concurrently across all three index algorithms under identical conditions, tracking exact microsecond durations and distance evaluation counters.
- **Viva Defense Point**: The initial warm-up run is deliberately discarded to prevent the KD-Tree's lazy tree construction from skewing subsequent query latency measurements.

---

### Step 10: Ground Truth Top-k Diff & Statistical Repetitions
- **Tab & URL**: Compare (`http://127.0.0.1:8080/#compare`)
- **Action**: Scroll down to the **Top-k Results Ground Truth Diff** table on the Compare tab.
- **Audience Sees**: Side-by-side columns comparing Brute Force (Ground Truth), KD-Tree, and HNSW results: exact rank matches receive green checkmark badges, while any ranking discrepancies or missing IDs are highlighted with warning badges.
- **Explanation**: Brute force linear scan provides the mathematically exact ground truth ($1.0$ recall), against which approximate nearest neighbor (ANN) recall is rigorously evaluated.
- **Viva Defense Point**: HNSW achieves 10x-50x speedups with $>98\%$ recall, while KD-Tree degrades in high dimensions due to the curse of dimensionality.

---

### Step 11: Viva Defense Discussion & Known Limitations
- **Audience / Examiners Ask**: *"What are the primary architectural trade-offs and limitations of this system?"*
- **Speaker Defense Response**:
  1. **High-Dimensional Partitioning**: The KD-Tree index provides exact nearest neighbor search, but at dimensions $>16$ its branch pruning degenerates toward brute-force linear scanning.
  2. **Memory Overhead**: HNSW maintains multi-layer adjacency lists in RAM, requiring higher memory overhead per vector compared to flat brute-force arrays.
  3. **In-Memory Volatility**: The current implementation stores vectors in memory without write-ahead logging (WAL) or disk persistence across restarts.
  4. **Plain-Text Parsing**: The document ingestion engine accepts `.txt` and `.md` files; enterprise PDF/DOCX binary parsing and OCR are out of scope for this core engine.
  5. **Indicative Browser Timings**: In-browser benchmarks include HTTP JSON serialization and network overhead; rigorous academic paper benchmarks are executed via the pinned C++ benchmark suite (`scripts/run_benchmarks_pinned.ps1`).
